# Устройство Kospet Map Maker

.NET 10, Avalonia 11 (GUI). Ядро (`Core/`) не зависит ни от GUI, ни от внешних библиотек:
чтение PBF, геометрия, изолинии и запись формата часов написаны с нуля, используется только
стандартная библиотека (`ZLibStream`, `GZipStream`, `MD5`, `HttpClient`, `System.Text.Json`).

## Модули

| Файл | Назначение |
|---|---|
| `Program.cs` | точка входа; `--cli` → консольный режим (`Cli`), иначе окно |
| `MainWindow.axaml(.cs)` | окно: выбор региона, слои, вывод, журнал; сохранение настроек |
| `MapPreview.cs` | контрол превью: читает готовые `.mlp`, рисует с панорамой и масштабом |
| `Loc.cs` | строки интерфейса RU/EN |
| `Core/Pipeline.cs` | весь процесс сборки: источник → OSM-слои → рельеф |
| `Core/Sources.cs` | индекс регионов Geofabrik, загрузки с кэшем, тайлы SRTM |
| `Core/Pbf.cs` | минимальный разбор protobuf и блоков `.osm.pbf` |
| `Core/OsmBuilder.cs` | классификация OSM-объектов и построение геометрии слоёв |
| `Core/Geometry.cs` | кольца мультиполигонов, ориентация, точка-в-полигоне, буфер линий |
| `Core/Contours.cs` | чтение `.hgt`, marching squares, запись квадрата рельефа |
| `Core/Yzl.cs` | запись/чтение формата часов: YZL, `.mlp`, R-дерево `.idx`, dBase |

## Конвейер (`Pipeline.RunAsync`)

```
 Geofabrik .osm.pbf ──► OsmBuilder (3 прохода) ──► roads / water / landuse ──► Yzl.WriteLayer
                               │
                               └─► набор квадратов 1°, задетых объектами
                                          │
 AWS skadi .hgt.gz ◄──────────────────────┘
        │
        └─► Contours.MakeTile (на каждый квадрат) ──► <name>-cm/<квадрат>/
```

1. **Источник.** Регион Geofabrik (скачивается в кэш, переиспользуется сутки) или локальный файл.
2. **OSM → слои.** `OsmBuilder.Build`, см. ниже.
3. **Запись слоёв.** Папка `<out>/<name>` пересоздаётся (`ClearMapDir` удаляет старую, только если
   в ней нет ничего, кроме `.mlp`/`.idx`/`.db`, иначе сборка останавливается); пустые слои не пишутся.
4. **Рельеф.** Для каждого квадрата, в который попал хотя бы один объект карты, скачивается
   тайл высот (если тайла нет — это открытый океан, факт кэшируется файлом `.missing`) и
   строятся изолинии. Квадраты без изолиний не пишутся.

Прогресс отдаётся колбэком `(stage, fraction)`; `fraction = −1` — неопределённый.
Отмена — через `CancellationToken` на каждом блоке PBF и каждом квадрате.

## Чтение OSM (`Pbf.cs`, `OsmBuilder.cs`)

### Формат PBF

Файл — последовательность `[u32 BE длина][BlobHeader][Blob]`. Обрабатываются только блобы
`OSMData`, сжатые zlib (или несжатые). В `PrimitiveBlock` читаются таблица строк,
`granularity`, `lat_offset`, `lon_offset` и группы: `Node` (1), `DenseNodes` (2), `Way` (3),
`Relation` (4). Упакованные поля разбираются вручную (`Pbf.PackedUInt`, `Pbf.PackedDelta`
— zigzag + дельта-кодирование).

Координаты переводятся в целые единицы 10⁻⁷ градуса:
`(lat_offset + granularity · lat) / 100`.

### Три прохода

PBF упорядочен как «узлы → линии → отношения», а нужно наоборот, поэтому файл читается трижды.
В памяти держатся только нужные данные — это позволяет обрабатывать крупные страны.

1. **Отношения.** Отбираются `type=multipolygon|boundary`, у которых теги дают класс воды или
   землепользования. Запоминаются id линий-членов и их роль (`inner` или внешняя).
2. **Линии.** Для каждой линии с тегами вычисляются классы (дорога, вода, землепользование,
   река-линия). Сохраняются отобранные линии и линии-члены отношений; все их узлы собираются
   в список нужных id.
3. **Узлы.** Список нужных id сортируется и дедуплицируется; координаты узлов из файла
   раскладываются по нему бинарным поиском.

Чтобы не тратить память на теги, из таблицы строк берутся только интересные ключи
(`Classes.Interesting`).

### Построение геометрии

| Объект | Как строится |
|---|---|
| Дорога | линия как есть (узлы вне выгрузки пропускаются) |
| Площадной объект из замкнутой линии | полигон из одного кольца, только если найдены все узлы |
| Мультиполигон | `Geometry.JoinRings` склеивает линии-члены в замкнутые кольца по совпадающим концам (с разворотом при необходимости); незамыкаемые остатки отбрасываются |
| Река-линия *(опция)* | `Geometry.BufferLine`: полоса шириной 25 м (`river`), 15 м (`canal`), 10 м (`stream`); в тоннелях не строится |

Полигоны приводятся к соглашению Shapefile (`Geometry.Polygon`): внешние кольца по часовой
стрелке, дыры против; каждая дыра приписывается внешнему кольцу, в котором лежит её первая
точка, и записывается сразу за ним.

`BufferLine` работает в локальной метрической проекции (равнопромежуточная по средней
широте линии): смещает каждую вершину по биссектрисе нормалей соседних отрезков, длина
смещения ограничена (miter limit 2), затем левая сторона + правая в обратном порядке → кольцо.

### Классификация (`Classes`)

Основные таблицы повторяют Geofabrik (коды — в [FORMAT.md §6](FORMAT.md#6-коды-классов)).
Сверка с официальной выгрузкой Geofabrik: у 99,5 % объектов, присутствующих в обеих
выгрузках, класс совпадает (расхождения — объекты, перетегированные в OSM за прошедшее время).

Порядок проверки для землепользования: `landuse` → `natural` → `leisure` → (доп. классы).
Один и тот же объект может попасть в два слоя (например, `landuse=reservoir` — только вода,
а лес с `natural=wetland` — и в воду, и в землепользование).

**Доп. классы** (опция «доп. классы») — теги, которых нет в схеме Geofabrik, привязаны к
кодам, для которых у часов уже есть стиль:

| OSM | → код |
|---|---|
| `natural=grassland`, `landuse=village_green`, `flowerbed`, `leisure=golf_course` | 7218 grass |
| `natural=fell`, `tundra` | 7219 heath |
| `natural=bare_rock`, `scree`, `shingle`, `rock`, `sand`, `beach` | 7214 quarry |
| `landuse=plantation` | 7215 orchard |
| `landuse=greenhouse_horticulture` | 7229 farmland |
| `landuse=construction`, `brownfield`, `railway` | 7204 industrial |
| `landuse=religious` | 7203 residential |
| `landuse=education` | 7209 commercial |
| `leisure=garden`, `dog_park` | 7202 park |
| `landuse=basin` | 8201 reservoir (вода) |

Фильтры дорог: «тропы» = 5151–5155, «проезды» = 5141, «грунтовки» = 5142–5147.

## Рельеф (`Contours.cs`)

**Данные.** Тайлы SRTM в формате `.hgt` (big-endian `int16`, строка 0 — северный край) из
[AWS Terrain Tiles](https://registry.opendata.aws/terrain-tiles/), набор `skadi`:
`https://s3.amazonaws.com/elevation-tiles-prod/skadi/N55/N55E037.hgt.gz`. Тайлы 1″ (3601²)
прореживаются каждой третьей точкой до 3″ (1201²) — как в стоковых картах. Значения < −1000
(пропуски) → NaN, такие ячейки пропускаются.

**Алгоритм — marching squares.**
- Угол ячейки «выше уровня», если `h ≥ L`. Для каждой ячейки перебираются только уровни
  в интервале (min, max] её углов; уровни ≤ 0 не строятся.
- Каждый отрезок соединяет два **ребра** сетки, а не точки. У каждого ребра глобальный id
  (горизонтальные `j·n+i`, вертикальные `n²+j·n+i`), поэтому соседние ячейки стыкуются
  точно, без сравнения плавающих координат.
- Седловые случаи (5 и 10) разрешаются по среднему четырёх углов.
- У каждого ребра не больше двух соседей, так что сборка в полилинии — простой обход:
  сначала цепочки от рёбер с одним соседом (упираются в край тайла или пропуск), затем
  оставшиеся замкнутые петли.
- Точка на ребре — линейная интерполяция; координаты: `lon + i/(n−1)`, `lat + 1 − j/(n−1)`.
- Линии короче 3 точек отбрасываются.

Сравнение с эталонной реализацией (contourpy) на тех же тайлах: число линий отличается
примерно на 1 % из-за разного разрешения седел и разбиения цепочек; геометрия совпадает.

## Запись формата (`Yzl.cs`)

- `BuildMlp` — записи по порядку, `recno = индекс + 1`; координаты `Math.Round(deg · 10⁶)`
  (округление к чётному).
- `BuildIdx` — R-дерево методом **STR**: объекты сортируются по X центра, режутся на
  `⌈√(N/10)⌉` вертикальных полос, внутри полосы — по Y, затем на группы по ~10 (не меньше 7,
  если это возможно). Уровни строятся снизу вверх, пока узлов не станет ≤ 15; они и
  становятся верхним уровнем. bbox записей — `float32` от исходных `double`.
- `BuildDbf` — dBase III; строки обрезаются по длине поля без разрыва многобайтовых
  символов UTF-8.
- `WriteFile` — заголовок YZL + MD5.

вручную (например, собрать слои программой и проверить их на часах).

## Как добавить новое

- **Новый тег → существующий стиль:** добавить строку в нужную таблицу `Classes`
  (`ExtraLanduse`, `ExtraNatural`, `ExtraLeisure`) или в `WaterClass`.
- **Новый слой.** Сначала выяснить, читает ли его прошивка: в стоковых картах других слоёв нет.
- **Другой источник высот:** заменить `Sources.GetHgtAsync`; `Contours.LoadHgt` принимает
  любой `.hgt`/`.hgt.gz` размером 1201² или 3601².
- **Проверка результата:** см. [FORMAT.md §7](FORMAT.md#7-проверка).
